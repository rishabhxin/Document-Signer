    Fundamentals

    What Is robots.txt?

    A robots.txt file is a plain-text file placed at the root directory of a website (for example, https://example.com/robots.txt) that provides crawling instructions to compliant search engine and AI web crawlers.

    • User-agent: Identifies which crawler receives the directives (* targets all crawlers without a dedicated section).
    • Allow: Explicitly permits crawling of matching paths, commonly used to allow a sub-file inside a disallowed folder.
    • Disallow: Asks compliant crawlers not to crawl matching URL paths or wildcard patterns.
    • Sitemap: Points crawlers to the full URL of your XML sitemap so they can discover indexable pages faster.
    Ready-to-reference snippets

    Common Robots.txt Examples

    Allow all crawlers with sitemap:

    User-agent: *
Allow: /

Sitemap: https://example.com/sitemap.xml

    Block private admin & AI training bots separately:

    User-agent: *
Disallow: /admin/
Disallow: /cart/

User-agent: GPTBot
Disallow: /
    Technical guidelines

    Robots.txt Best Practices

    • Place the file strictly at the root domain (/robots.txt), using lowercase filename and UTF-8 encoding.
    • Never block essential CSS, JavaScript, or image folders needed for search engines to render your pages.
    • Keep separate User-agent groups self-contained, do not assume a named bot inherits User-agent: * rules.
    • Always include full absolute URLs (https://...) in Sitemap: lines.
    • Test changes carefully before deploying so you do not accidentally block your homepage (Disallow: /).

    Important SEO & Security Warning

    A robots.txt file is a voluntary crawling guideline, it is not a security mechanism or an indexing removal switch. Robots.txt does not:

    • Guarantee that a URL will be removed from Google Search.
    • Protect private, confidential, or sensitive pages.
    • Prevent users or non-compliant bots from visiting blocked URLs directly.
    • Guarantee that blocked URLs will never appear in search results (if linked externally).

    For private content, use proper server-side authentication and access controls. To prevent search indexing of a page, use a noindex meta tag or X-Robots-Tag HTTP header instead of blocking it in robots.txt.

    Frequently asked questions

    Frequently Asked Questions

    1. Where should I place my robots.txt file? +

    Upload the file to the root directory of your domain so it is publicly reachable at https://yourdomain.com/robots.txt. Search engines only check the root path of each host or subdomain.

    2. Does Google support the Crawl-delay directive? +

    No. Googlebot ignores the Crawl-delay directive in robots.txt. Some other crawlers like Bingbot and Yandex may respect Crawl-delay, which is why it is optional and off by default.

    3. Does blocking a page in robots.txt remove it from Google? +

    No. Blocking a URL in robots.txt prevents Google from crawling the page, but the URL can still appear in search results without a description if other pages link to it. To de-index a page, allow crawling and add a meta robots noindex tag.

    4. Can I block AI bots like GPTBot or ClaudeBot without blocking Google? +

    Yes. Keep your standard User-agent: * rules for search engines, and click + GPTBot or + ClaudeBot above to add a separate User-agent group with Disallow: / specifically for those crawlers.

    5. Can I edit an existing robots.txt file here? +

    Yes. Click Upload Existing robots.txt at the top of the tool to load any plain-text robots.txt locally into the rule builder and raw editor, validate it for errors or conflicts, and download the updated robots.txt file.

    6. Is Open Sign Robots.txt Generator free? +

    Yes. It is 100% free with no login required, and everything runs locally in your browser without uploading your files or modifying your live site.
